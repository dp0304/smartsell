# 视频发布、排期与查回

## 自己的社媒账号状态与近期作品

For “查我的社媒状态” or “X 账号现有视频”, use the paired Worker through `worker_social_status_request` and poll `worker_social_status_get` for the same task ID. The Worker supports `account_status` and `recent_posts` according to the live schema. Follow the Worker-only request and reporting steps in the sibling data collection Skill. A specific existing SmartSell schedule is checked through its own target and linked publication receipt. [数据采集与核对](../smartsell-data-collection/SKILL.md)

## SmartSell 排期

Codex or Claude drives the workflow through the requested workspace's connected SmartSell MCP. Inspect the live tool list and schemas, or use `smartsell_operations_describe`. Prefer a named tool. Use `smartsell_operation_call` only for an operation the current credential is allowed to call and the live catalog describes. Keep all reads and writes in the same workspace. Resolve names from authorized context before asking for IDs. Never route through another account or device, or bypass MCP, approval, login or platform controls. The Agent handles tool calls and readback without asking the user to claim desktop tasks, copy session IDs or run commands.

1. **Locate and check.** Use available reads such as `workspace_get_context`, `account_list_social_accounts`, `content_list`, `content_get_variant`, `content_list_revisions` and `publishing_list_targets`. Match the platform, account, committed video revision and requested schedule (include the time-zone offset), or locate the existing target. A status-only request stays read-only. When exposed, use `account_check_operation` for `operation: "publish"`, `content_format: "video"`. Check the authorized execution paths and device binding. For a browser path, compare any current verified Chrome identity evidence with the requested account, device and session. A binding or open page alone does not establish identity. When no separate proof is visible, use the server precheck and report what it actually establishes. If the user specifies a device, proceed only when the configured route can honor it. The target schema does not select a device directly.
2. **Schedule and submit.** The user's request to schedule for publication or to publish is intent to submit through the approval flow. For a new target, call `publishing_create_target` with `body` containing `social_account_id`, `content_variant_id`, `revision_id` and the requested schedule (`scheduled_at` for a fixed time or `schedule_kind: "asap"` when requested and supported). Use `connector_mode_pref: "inherit"` for the configured route including an already authorized official API path, or `"assist"` for a verified, supported assist route when appropriate. Use the live schema. For a matching existing target, read it instead of creating a duplicate. Submit an eligible target with `publishing_request_approval`, `params: { id: TARGET_ID }`, `body: {}`, and the target's latest `expected_version`. Use a distinct `idempotency_key` per mutation and reuse it only for an identical retry. On a version conflict, reread before acting. Preserve the target and precheck details if submission is blocked.
3. **Follow execution.** Read `publishing_get_target` by the same target ID, `publishing_get_execution` for its linked task, and `posts_get` for a linked post when exposed. Once approved or covered by a valid standing grant, let SmartSell run the authorized official executor at the scheduled time. If the user explicitly requests immediate execution and the authorized official route and task allow it, use the public `publishing_run_now` operation with `params: { id: TASK_ID }`, the latest task version and an idempotency key. Honor the live schema and all prechecks. Read the same task back. A pending approval, queued or claimed task, or accepted platform submission is still pending. Report `published` only from a confirmed publication linked to the target, with the available evidence or permalink. For `outcome_unknown`, check the original task. If verification is requested and allowed, use `publishing_reconcile` to request verification with the current task version and a separate key. Preserve unknown status until evidence resolves it. Never assert absence, resubmit an unresolved attempt, invoke internal dispatch, change bindings, enable auto mode or approve on the user's behalf.
4. **Report the real boundary.** Give the account, revision, schedule, target/task IDs, plan, approval, execution and any concrete blocker. Ask only for unresolved choices or an actual authorization, Chrome login/MFA, or product review or reconciliation step. Douyin and Xiaohongshu currently use the assisted/manual publication path where official execution is unavailable. If SmartSell returns a human submission step, identify it after completing the available Agent work and check the same target again when the user follows up.
