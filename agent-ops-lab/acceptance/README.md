# SmartSell 终端全能力验收用例

从 Claude Code 或 Codex 接到「把这款桌灯从选品做到上架准备、内容发布和复盘」开始。运营人员在终端交代任务、看回执。Agent 自己找工具、读当前权限、按依赖顺序办理。Web 转发任务、呈现状态和审计。指定 Worker 使用自己那台电脑上的可见 Google Chrome，遇到登录或验证时由操作者接手。产品规定由人作出的审核和外部发布决定沿用现有入口。

### 固定测试数据

- 工作区 A 为本轮独立测试空间，内有品牌「棱镜」、中国和美国市场，本地时区 `Asia/Shanghai`。工作区 B 用于隔离对照，建立同名产品与不同素材。用服务端返回的 ID，所有创建的测试对象带本轮唯一批次标记 `QA-<run_id>`。
- 新品为「棱镜桌灯」，测试 SKU `PRISM-QA-01`，两种颜色规格。中国市场 CNY 129.00、库存 12，美国市场 USD 19.00、库存未采集。准备一行重复 SKU、一行非法库存和一行正确的修正 CSV。取回金额时断言币种和最小货币单位。
- 准备短 MP4、封面 PNG、多图、纯文字和两种语言的发布文案。小文件保留 SHA-256 和大小，视频走可播放检查。大于当前内联上传上限的测试文件验证可用上传入口和失败反馈。标题、文案、标签、封面和媒体锁定到对应内容修订。
- 本地可控网页、卖家样本、测试评论和模拟提供商回执均有已知值与来源。另准备看不到的字段、确实为零的指标、两条相同外部单号、一条修正订单、一次非提交错误和一次响应丢失。真实外站用指定测试账号或有测试权限的自有账号。
- 两个具有独立 `device_id` 的 Worker，A 绑定社媒账号，B 绑定测试店铺。先在同机两个实例做可重复回归，再用两台物理设备访问同一个 HTTPS 服务，分别验证 Windows 和 macOS 的支持项。两台电脑各自登录 Chrome，分别记录浏览器验证所对应的账号。
- 每轮至少用 Owner/Admin、Reviewer、写 Agent、只读 Agent、被拒绝或撤销的 Agent。使用不同授权记录检查工作区、品牌范围和有效期。用独立数据实例承载有冲突的异常分支，避免让一个失败阻断其他工具验收。

## 从终端下达的任务

每个编号都是一段可单独运行的终端对话。首次用一句业务指令让 Agent 执行，再在同一个会话追问「按刚才的任务／内容 ID 重新读，告诉我实际状态、原因、设备和回执」。追问只读，避免重复创建。下面指定的通过条件都需有实际回执。

<a id="t00"></a>
### T00 · 接入、权限和通信

> 连接我的测试工作区。告诉我当前账号能读、能写哪些东西。帮我对照只读和写授权，做一次普通查询、一次新增、一次只读写入请求，并在工作台找出各自的审计记录。

- 分别从 CC、Codex 对正常授权端点执行连接。记录 `initialize` 指定和协商的版本、`notifications/initialized`，再用 `tools/list` 翻页。比较两个授权的清单和 schema。启用了资源时验证资源模板和工作区范围。协商了 MCP Tasks 时按实际支持范围验证 `tasks/get`、`tasks/result` 和任务进度；未协商的可选功能按当前协议回执判定。业务作业、Worker 任务和 MCP Tasks 各记自己的 ID。
- 在支持浏览器 OAuth 的构建上，跑发起连接、Web 登录、批准或拒绝、回调、短有效期、自然到期和主动撤销。核对 Agent 名称、工作区、实际权限、授权人和到期时间。普通授权连接与旧 PAT 各跑一次，只有发现了相应入口才开始用。主仓仍只提供手工授权的构建，分别记录主仓结果与隔离 OAuth 结果。
- 只读授权对同一资源读取成功，写入失败且没有业务对象。外工作区和品牌范围越界看不到数据。同键同参的两次调用各有请求和审计记录，业务对象只出现一次。同键异参、旧版本和已撤销授权获得各自实际拒绝回执。无法归属身份的 401 记录在接入结果中。
- 通过条件。每次已认证的工具调用均可按实际 `X-Request-Id` 查回唯一 Web 审计行，核对 Agent 授权、工具、结果、错误码、时间和适用的任务或设备。无效请求 ID 查零行。 [现有主仓审计用例](../audit/main-integration.md) · [OAuth 隔离验收](../audit/README.md)

### T01 · 工作区、市场和日常工作

> 查一下棱镜品牌的中美市场。把这轮新品运营相关的工作、负责人、截止日期和异常整理好，让我能从终端重新看到产品、计划、日历和待办。

- 从工作区上下文读取品牌、市场、时区和可用账号。创建或更新本轮测试品牌、区域、工作项、依赖和负责人，设置一项未读通知、一项到期任务和一项已完成任务。更新一项个人视图或保存搜索，并验证只有拥有者能读。授权外的品牌用同名数据作对照。
- 通过条件。复读返回新品牌、市场和任务的正确 ID，任务交接和批量变更反映到工作列表。搜索、首页、产品、计划、日历、社媒、广告、待决定、活动和 Agent 在线视图能分别定位本轮可见记录。每种筛选返回已知记录，分页无漏项或重复。 [工作区验收](../../docs/acceptance/workspace-results.md)

### T02 · 多 Worker、Chrome 身份和登录异常

> 核对 A 的社媒账号和 B 的店铺，不互相领任务。让 A 查看自己的知乎统计。让 B 继续做绑定店铺的商品导入。先告诉我哪台需要登录，登录好以后再核对并继续。

- 让 B 在线、A 离线，先只派给 A，B 领取为空。A 上线后，从终端分别派发已授权的浏览器社媒、商品导入和知乎只读任务，核对 Worker 空闲时自动签名领取、同一设备同时只有一个有效租约。登录资料能匹配时，待核验的既有账号绑定由 Worker 签名回报。空队列保持安静。记录各平台实际需要的登录、审核或交接步骤。在另一轮中让 A 断线或急停，核对阻塞、结果未知、租约到期和重领。过期结果和错机结果应被拒绝。
- 各账号分别执行「未登录 → 用户登录 → 页面可见身份与绑定吻合 → 关闭或过期 → 换账号」。遇到验证码、二次验证或身份不符时暂停。可识别的知乎登录页按原任务上报 `login_required`，用户完成登录后再按终端工作流复查。无明确登录证据时记实际阻塞或过期。
- 通过条件。A、B 的设备和任务不串。每个真正验证过的账号或店铺有页面身份、时间和归属；在同一设备的 Chrome 执行和回传。成功或异常都能按任务 ID 查回。 [Worker 证据](../desktop/README.md) · [知乎签名回填](../zhihu/signed-run.md)

| 平台 | 必测行为 | 真实完成的证据 |
|---|---|---|
| 知乎 | Chrome 登录检查、本人主页统计、账号不符 | Worker 实际打开本人入口，回报页面原文，终端读回同一任务。 |
| 抖音、小红书 | 逐个平台核对已登录创作者身份、冻结内容、交接和发布回执 | 经批准的测试账号上提交后，使用作品链接、作品 ID、账号和可见性独立回读。 |
| YouTube、Facebook、X、Instagram、Reddit | 五个平台各自验证 Chrome 身份和登录过期 | 实际账号页面确认归属。若该构建和授权另提供对应发布能力，独立执行 T07；没有目标能力时验证能否返回可查的原因。 |
| Shopify、Amazon、Shopee（虾皮） | 三家各验店铺身份、固定 Worker、导出任务、导入预览 | 官方卖家后台能核对店铺和导出来源。远端上架按 T03 的独立回执验证。 |
| TikTok 与 TikTok Shop | 按构建公布的官方接入或手机交接验证账号、任务、目录和权限 | 用实际支持的授权记录与平台查询，核对草稿、发布 ID 或商品快照。手机夹具和实体手机单列。 |

### T03 · 商品、价格、库存、导入与上架

> 把 B 店铺里的桌灯导进来，先报错行，再修到可以确认。给两种规格建立中美价格和库存；需要上架时告诉我平台是否真正产生了商品。

- 查已绑定 Worker 和店铺，创建并读回导入任务。用合法店铺测试导出文件，覆盖 CSV、TSV、XLSX 与错误列重映射，核对成功、拒绝和重复行。确认后查商品、SKU、变体分组和外部映射。对同一 `SKU + 市场` 验证币种、价格、库存和来源，确实为零与未采集分别保留。再测商品事实修订、翻译稿、促销草稿、订单退款和库存规则。
- TikTok Shop 单测目录与库存权限。供方样本价格 USD 20.00，库存关闭时回读价格、空库存和 `unknown`。只有订单权限时，回读授权不足，目录同步次数为零。 [目录和库存回归](../../docs/acceptance/tiktok-catalog-inventory-results.md)
- 两条独立上架用例。当前桌面上架返回 `unsupported`，重试应读回同一业务回执，商品变更和 Worker 上架任务增量都为零。某平台提供可写沙箱时，对批准的测试 SKU 调用已发布的工具，在卖家后台独立查商品 ID、SKU、店铺、价格和状态，重复请求只生成一件。绑定和导入分别留回执。
- 通过条件。导入批次、失败行原因、价格快照、草稿与外部商品可按 ID 区分，商品版本和来源能回读。 [现有商品对话](../scenarios/README.md) · [商品规格和价格验收](../../docs/acceptance/commerce-variant-results.md)

### T04 · 数据采集、同步和研究

> 采集测试页面上的商品名、SKU、价格、库存和链接，保存来源和时间。明天用相同范围再查时要能区分新数据、重复数据和没采到的数据，再把能用的资料整理成研究笔记。

- 先核对来源及允许用途。分别对自建公开样页、授权平台可见数据、合成 CSV、增量同步、回补和 Webhook 样本验证。正常页读取预设字段；未授权、过期和无数据各有状态。相同事件 ID 重放一次，观察去重和窗口计数；中途报错后从检查点恢复。分别查询来源批次、原始引用、数据质量和告警。
- 将本轮观测放进研究板，保留证据和用途，查询趋势、品牌提及、竞品观察、告警和创意参考。仅有引用许可的素材可保留引用。页面文本作为采集内容保存。
- 通过条件。按来源和时间能复查实际页面值。短时间窗查到已知 1 条，远窗口查零条，缺字段保留缺失语义。证据、研究笔记和引用 ID 可串起来。 [已有采集对话](../scenarios/README.md) · [数据质量验收](../../docs/acceptance/ingest-quality-results.md) · [研究能力验收](../../docs/acceptance/intel-results.md)

### T05 · 活动、简报、目标和内容矩阵

> 做一份桌灯上市计划，关联 SKU 和中美市场，设置浏览与转化目标，给每个渠道安排内容，先把简报和预算草稿交我核对。

- 继承 T03 的商品 ID 和实际可用指标。创建活动、目标、计划位和简报修订，配置市场、语言、协作者、依赖和预算草稿。将两个渠道分别从草稿推进到合法的下一状态，回读活动矩阵、实际成本和完成差距。放入一条同名但不同品牌的活动作为对照。
- 通过条件。活动 ID、商品及市场关联、目标基线、内容位数量、简报修订和预算金额吻合。修改一个渠道时另一个渠道可见结果不变。需人决定的预算和结案只记录送审或拒绝。 [活动验收](../../docs/acceptance/campaign-results.md)

### T06 · 视频、图片、文字、版权和内容修订

> 把短片、封面、多图和纯文字做成四种内容版本。文案用「棱镜桌灯，售价 129 元」，加 #桌灯 和 #暖光，链接 T03 的价格和已批准商品事实。给我看送审前究竟是哪一版。

- 通过已授权接口实际传输测试媒体并比对字节、哈希与预览。分别验证有效版权、将到期版权、只可引用和未批准知识。建立素材文件夹、不同素材版本、封面与主媒体。改标题、标签和翻译，提交新修订，复读旧修订和当前草稿。

- 通过条件。按版本回读媒体、文字、标签和商品事实；重导或更改草稿不会改变已批准的历史内容。 [已有文件与内容用例](../gateway/README.md) · [发布完整性验收](../../docs/acceptance/publishing-integrity-results.md)

### T07 · 审批、三分钟排期、执行和回执

> 把审核版设到创建排期后约 3 分钟发布在指定测试渠道。保留一条待审对照，到点再告诉我哪条执行、哪条没执行、平台回执是什么。

- 以服务端保存的时间为准，记录 `scheduled_at − created_at`。同一排期目标在到点前、到点、到点后至少 15 秒各读一次。保留一个未获批的目标；第二个分支用合法人工批准和已验证的测试账号；另建一条退回并修改的内容，校验旧批准和新修订的绑定。用第三个目标测取消、暂停和审批与预检冲突。
- T03 的中国市场从 CNY 129.00 改为 139.00，触发使用旧价的目标重新核对。另一市场或独立渠道的目标用自己的快照。改期、预检、编排预览与提交各有回执。发布进入可执行条件后核对目标、执行尝试、账号、设备、冻结修订和平台选择的发布方式。
- 在测试沙箱验证限流、断线或者提交后回执丢失时，先用原尝试 ID 对账。唯一平台作品计数是 1。真实发布需要独立的作品 ID、官方链接和可见性读回；当前需要人工交接的渠道记录交接和实际提交人。未获批的目标到点后仍待审批，无执行尝试或平台帖子。
- 通过条件。计划状态、平台结果和证据分别对上同一目标，用户可在终端看到当前进度与待处理原因。 [三分钟实测](../scenarios/three-minute/README.md) · [发布流程验收](../../docs/acceptance/publishing-results.md)

### T08 · 创作者、寄样、交付和结算准备

> 给本轮活动安排两位测试创作者，整理试用样品、交付物和佣金测算。先看已签条款和历史作品，再回报交付核验状态。

- 用合成联系记录和授权公开资料接入创作者，建立账号关联、活动关联、合作与条款草稿。创建两份交付，一份待审、一份模拟人工接受。登记合成寄样状态、试播安排和直播结果，核对收件人与合作归属。生成评估和佣金草稿，加入一条退款后冲减。
- 通过条件。工作项、条款版本、内容证据、评估来源和退款口径能追溯。同一交付不重复结算。验收交付、佣金批准、确认付款按各自人的权限流程留下状态。 [产品验收矩阵的创作者模块](../../docs/acceptance/matrix.md#cr)

<a id="t09"></a>
### T09 · 评论、私信、评论回复和交接

> 整理两条测试评论和一条私信，认领后写回复草稿。普通问题走批准后回复，人工渠道给我官方原文入口，最后把没解决的交接出去。

- 覆盖会话筛选、未读、标签、认领／释放、二人抢占、续期、案例、内部备注、评价及响应质量。对支持的队列先草拟、再由有权限的人批准，查回复回执；小红书等仅支持人工的任务保留原文入口、操作者、时间。带外站重试回执的场景独立核对同一回复 ID。
- 通过条件。错租约或未审批未发送，终端报告可解释，Web 有对应审计。来自平台的真实回复须在测试账号看到相应内容及 ID。重复或原帖编辑保留原记录和来源。 [互动验收](../../docs/acceptance/engagement-local-results.md)

<a id="t10"></a>
### T10 · 链接、页面、表单和线索

> 给桌灯活动配短链、UTM、落地页和线索表单，走一遍测试访客路径。我需要查到是哪条链接带来的这条线索。

- 建立测试短链、UTM 模板和允许的测试目的地，准备落地页、个人链接页和表单草稿。用测试访客输入合成数据，校验一次点击和一次提交的会话标识、来源、同意记录、重复提交行为与线索去向。检查停用、失效、地址不匹配和未批准上线。公开上线、启用和域名操作用产品已有的授权流程。
- 通过条件。每项草稿和已批准动作能按 ID 查回，表单事件和来源参数一致，重复提交或被停用的入口不会多记线索。 [流量验收](../../docs/acceptance/traffic-metrics-results.md)

<a id="t11"></a>
### T11 · 广告计划、报表和调整

> 用当前素材做一个测试广告提案，预算 500 元，按两个版本比较，给我说明投放和调整要经过哪一步审批。

- 读取测试广告账户、素材和权限。使用最小货币单位创建提案、产生一次修订并送审，验证预算、时区、投放周期。导入提现有测试效果的报表，区分估值与实际，记录调整建议并按授权人员批准。允许有测试提供商时，分别验证 API 接收、独立读回和未知结果时的对账。
- 通过条件。方案修订、支出、指标、平台操作状态彼此吻合。未批准时没有投放或扣费。正式花费及平台写入只在明确授权的环境验收。 [广告验收](../../docs/acceptance/commerce-ingest-ads-results.md)

<a id="t12"></a>
### T12 · 客户、同意、分群与触达

> 用合成客户把线索分组，准备一封测试邮件。对退订和同意冲突的人要单独标出来，最终给我看实际可发送人数。

- 读客户、身份、合并历史、同意记录与分群。构造一个已同意、一个已退订、一个冲突、一个重复身份，预期合成客户去重且抑制生效。建立邮件和自动流程草稿，在回环 ESP 测试批准后的发送、回执、重放、失败对账和退订。测试名单仅用受控测试接收端。
- 通过条件。分群预览的人数、实际接收端与持久化回执一致。被抑制客户计数为零发送，拒绝和待审状态可从终端和 Web 复核。 [生命周期验收](../../docs/acceptance/lifecycle-delivery-results.md)

<a id="t13"></a>
### T13 · 数据复盘、归因、实验与报表

> 汇总这轮桌灯的播放、加购、订单、退款、广告成本和收入，按中美市场算归因。给我一份能追到原始行的报告，再看一次数据修正会不会改掉旧报告。

- 准备同一外部单号重复输入、一次退款、日与累计指标、0 与缺失、不同币种与报告日。登记实际观测，查询产品和活动表现、受众、队列、推荐时段、成本和贡献。分别创建归因模型计算、报告版本、模板、导出队列以及实验草稿和只读结果。退订/缺权限/低样本按产品实际状态返回。
- 通过条件。按既定口径对账，重复外部单号只计一次。修正订单只影响新计算，已定稿报告指向原批次和行号。报告导出和实验启用按各自授权，负责人可从结果追溯来源。 [归因和报表验收](../../docs/acceptance/attribution-evaluation-results.md)

<a id="t14"></a>
### T14 · 工作交办、并发领取、续租、取消和结果交接

> 接起工作台交办的三项：整理商品、做待审排期、更新复盘。两位 Agent 同时在线，确保每项只被正确接手一次；其中一条留给另一位接力。

- 先让已授权的 CC 或 Codex 在线，再从工作台触发待领任务。以触发时间为起点，核对 Agent 是否自行收到任务、自动认领和回报进度。关闭客户端再触发一条，记录排队，并在恢复后核对同一 ID。若需要手工启动客户端或主动查询，把这一动作记进结果。终端发起的任务另外验证其通过 Web 转发到指定 Worker 的过程。
- 使用两条独立连接并发认领同一项，核对成功者；用错误版本、旧租约、撤销凭据尝试续租。按实际接口测试取消及确认、暂停、接力、退回、验收、模板及受审变更集。角色动作保持各自授权。
- 通过条件。只有有效领取者能提交，重复提交保留原结果，已确认的交接或取消能从另一端重新读到。待领取状态和已提交产物分别记录。 [Agent 生命周期验收](../../docs/acceptance/agent-lifecycle-results.md) · [长任务验收](../../docs/acceptance/agent-long-operations-results.md)

### T15 · 运行状态、异常反馈和验收收口

> 查本轮所有任务，列出已完成、需要登录、等待审批、能力不可用、超时和失败各有多少。每条给出原任务 ID、发生时间和最新状态来源。

- 用可观察的测试状态验证运行健康和两个 `ops` 查询。重启检查原数据持久性。运行所有模块的状态读取，与服务端日志和桌面签名回执核对。执行失去网络、权限撤销、响应未知、停止、租约过期的分支，检查错误提示与处理人。结束后撤销本轮临时授权，确认原审计还能由授权管理员查到。
- 通过条件。每个异常可按任务、设备或请求 ID 查回。已完成业务能找到对应结果，未完成进度有实际阻塞而且没有虚假的执行回执。 [主仓 Web 审计](../audit/main-integration.md)

## 逐项验收怎么做

连贯跑一遍时，先完成接入和设备配对（T00–T02），再建商品、取数据、做活动和定稿（T03–T06），最后到期执行、互动和复盘（T07–T15）。需要已完成任务才能核验的视图留到第二轮读回。单独运行某段时，先用固定数据建立依赖对象，并把它们的真实 ID 传给该场景。三分钟排期从设备已就绪后的实际写入时刻算。

1. 固定产品版本、运行入口、工作区、角色、授权和平台环境。用当次 `tools/list` 以及通用入口按模块返回的目录生成集合，和两个 CSV 双向求差。新增项先补用例。移除项记录权限或版本原因。对两个入口的同名工具分别校验。
2. 对每个可见子操作使用本行场景的有效数据和当次 `smartsell_operations_describe` 结构。读取至少验证一个已知非空对象及实际字段；对分页、过滤、过期和零结果测边界。写入先记作用域、状态与版本，再对回执和独立读回验证具体变更。预览或纯计算验证输入、输出以及无持久写入。人工专用操作验证目录可见性、实际拒绝以及原业务状态。
3. 用原生 CC 和 Codex 跑自然语言对话，记录它们如何选择 Skill、如何读回状态。用标准 MCP SDK 独立跑每个具名条目及每个可自动化子操作，以声明 schema 校验结果。原生进程配合确定性模型夹具的矩阵只证明客户端与服务通信，在线自然语言场景才验证 Agent 自己选择工具。可控网页、平台沙箱和真实站点的证据注明来源。
4. 每条记录至少保存用户指令、Agent 可见答复、实际工具与子操作、客户端和产品版本、授权 ID、脱敏输入引用、返回码、服务端请求 ID、Web 审计 ID、时间和独立读回。桌面任务再保存同一 `task_id` 的分派、设备签名领单、浏览器所见、签名回报与终端回读。外部动作补平台对象 ID、可见证据和操作者。凭据、签名值和会话内容留在各自客户端。授权撤销、401、只读拒绝按实际可归属范围记录。
5. 表中每条结论独立判定。协议有回执、有效空结果、在队列、通过审批或 `unsupported` 都只对应本身的验收点。业务断言通过需要验证具体结果。需要外部沙箱、授权平台、实际 Windows 包或第二台物理机的行，保留明确的环境缺口。保留历史跑次，新跑次使用新目录。

### 用现有驱动复跑基线

从项目根目录使用 Node 24。第一条运行两种 MCP 入口的具名工具矩阵，第二条运行现成的通用子操作夹具。两条命令各创建独立测试工作区，并输出该次证据目录。

```sh
MATRIX_SMARTSELL_SOURCE="$PWD" node --import tsx agent-ops-lab/coverage/run.mjs
SMARTSELL_SOURCE="$PWD" node agent-ops-lab/gateway/run.mjs
```

两张清单的证据列引用基线。上述驱动已有的能力和这套用例的新覆盖目标分别计数。新增对话、只读授权用例和外部平台回执按本章规则归档。 [现有具名矩阵复跑说明](../coverage/run-main-EH9S3A/REPORT.md#复跑) · [通用入口复跑说明](../gateway/README.md#复跑)
