# SmartSell 實作審核、介面優化與待完成計畫

審核日期：2026-11-20　對照基準：`plan.md`（D0.3）附錄 A 的 147 項功能　審核對象：commit `cc54039`

## 1. 結論

- **介面**：主要問題不在視覺，而在系統把 API 直接搬到畫面上。表單會顯示 `POST /publish-targets`，並要求操作者手打「內容變體 ID」「凍結修訂 ID」「對話占用權杖」或 JSON。每個模組都有一個「進階操作」分頁，列出全部原始 API。另外還並存兩套工作台，兩邊的資料不同步。這些就是「反人類」「操作邏輯混亂」感受的主要來源。第 2、3 節是這次已處理的部分。
- **功能**：後端規則大多寫得很完整，包括修訂不可變、審批綁定內容雜湊、結果未知、提交許可、租約權杖。主要缺口有三：
  - 兩套資料模型（Commands、Operations）並存且不同步。
  - 很多寫入動作沒有介面，只能走進階操作或相容版工作台。
  - 外部平台大多只做了一半：只有 YouTube 能經官方 API 發布；IG/FB 的發布程式寫了，但沒有接進執行流程；收件箱沒有接任何平台；連接器和 Android 手機控制尚未實作。
- **`docs/acceptance/matrix.md` 的數字不等於功能完成**：它寫「147 項皆有通過的本地證據」，意思只是每項都有測試，不代表功能完成。逐項核對後，大部分功能是「部分」。見第 4 節。

## 3. 這次修改的內容

**介面（`apps/web/src`）**

- `OperationForm.tsx`：新增參照選擇器，涵蓋單選、多選勾選清單與連動選單。只有一個選項或有多個修訂時自動預選；沒有選項時提示「前往建立」。選項標籤中文化，時區改成下拉。少用的欄位收進「更多設定」。送出後顯示「已完成＋檢視／完成」。API 路徑與 JSON 只在開發者模式顯示。
- `actions.ts`：
  - 排期改送 `local_scheduled_at`＋`schedule_tz`，由後端處理日光節約時間。原本在瀏覽器換算時區，跳過的時刻會被默默平移。
  - 工作稿改成直接編輯文字，不再要求 ProseMirror JSON。
  - 「檢查帳號能否發布」與「設定活動商品」改為勾選清單。原本活動商品會送出後端不接受的 `items`。
  - 「轉人工」的接手人改為成員下拉。
  - 內容語言、店鋪語言改成下拉。
  - 平台清單改為後端支援的值：加入抖音、小紅書；移除 X、Threads、Pinterest、LinkedIn，後端不接受這四個。
  - 「新增選題」加入必填的來源連結。原本缺這個欄位，每次送出都失敗。
- `main.tsx`、`workspace-tools.tsx`、`preferences.ts`：側欄重新分組，「設定與管理」可收合，加入開發者模式開關，頂欄精簡，相容版入口改為開發者限定。
- `WorkspaceViews.tsx`：
  - 分頁太多時收進「更多」選單；進階操作、原始 JSON、匯入批次 ID 輸入框改為開發者限定；移除重複的「CSV 匯入」按鈕。
  - 加入下一步提示、可讀的詳情標題、依頁面說明的空白狀態；狀態與選項值中文化。
- `dashboard.tsx`、`workspace-onboarding.tsx`：首頁指標改版；加入「開始使用」清單並自動重新檢查；設定頁每一步加上「前往處理」，「受阻」改稱「未完成」。
- `primary-search.tsx`（新）：主工作台的全域搜尋。
- `record-filters.tsx`、`commerce-workbench.tsx`、`campaign-workspace.tsx`：篩選器顯示名稱；沒有店鋪時引導先建店鋪；「新增活動市場」帶入市場語言，原本必定 422。

**後端（審核時找到並確認的 bug）**

- `workspace/configuration.ts`：
  - 首次設定的「社群帳號」步驟用錯了操作名稱，應為 `account_get_capabilities`，所以永遠過不了。
  - 「測試草稿」步驟用錯了內容階段值，所以永遠過不了。
  - 新增 `only_if_passed`：首頁在背景重新檢查時，只記錄已完成的步驟，不會把未動過的步驟改成「未完成」，因此「繼續設定」仍會停在管理員實際卡住的那一步。
- `agent/models.ts`、`integration/agent-model-runtime.ts`：Anthropic 直連補上 `/v1`；模型呼叫逾時從 5 秒改為 120 秒，可用 `SMARTSELL_MODEL_TIMEOUT_MS` 調整。
- 前端另外修正：團隊、AI、採集三個模組的「範本」分頁，原本會誤開素材文案範本的建立表單。

**測試**

- 依賴開發者介面的 E2E（相容版、工具面板、進階操作）改為在測試開始時開啟開發者模式。
- 表單 helper 支援下拉選單，斷言改用新的文字。
- `docs/acceptance/matrix.md` 因測試行號改變而重新產生。

## 4. 功能審核結果

審核方式：三個審核代理分組逐項讀程式，對照各模組 x.12 的 P0 驗收要點；部分 bug 由主審再次核對。

狀態定義：
- **完成**：後端加介面都可用。
- **僅後端**：只有 API 或 MCP。
- **部分**：缺少設計中的關鍵規則或介面。
- **模擬**：外部呼叫不是真的。
