`integration/{publish-host,publish-device,publish-connector,workspace-services}.ts`, and in wave 2 (E8) `bootstrap.ts`, `app.ts`,
`planning/index.ts` and `packages/domain/src/publishing/**`. Review of S2: `S3-review-of-S2.md`.

## What other streams can use now (C3, C14)

From `apps/server/src/modules/worker/index.ts`: `isWorkerRoute`, `dispatchWorkerJob`, `requestRevoke`, `revokeForTarget`, `moveQueuedChannelJobs`,
`createCheckLoginJob`, `latestJobForTarget`, `isMachineOnline`, `machinePresence`, `bumpSyncGeneration`, `deviceSyncState` (newest change per machine,
for `sync_behind`), `syncTaskFromJob`, `ACTIVE_JOB_STATUSES`, `JOB`/`EVENT` kind names. Events: `worker.job.status_changed` (C3 payload, emitted
after the row update in the same transaction), `worker.job.late_fact`, `worker.job.dispatched`. `ctx.presence(deviceId)` is injected by
`workspace-services.ts` for every Operation, background run and device request (it yields to a row another writer stamped).

The S2 hooks (`setWorkerEngineHooks`) are installed by `modules/worker/engine.ts`, which `execution/service.ts` imports, so they are live wherever
planning/execution load — not only after `discoverOperations()`.

## S4 (posting API and MCP)

1. `hub_channels_check`: call `createCheckLoginJob(ctx, accountId, { openLoginWindow })`; an open check for the account is returned again.
   `hub_posts_schedule`: same function when `browser_session.checked_at` is older than `LOGIN_CHECK_MAX_AGE_H`.
2. `post_update cancel` goes through planning `cancel()` → Worker-aware `requestCancellation`: it throws 409 `POST_LOCKED` (submitting/result_pending) or
   409 `POST_RESULT_UNKNOWN` (outcome_unknown/unreported); otherwise the target is `cancelled` (no job or queued) or `cancel_requested` (task
   `cancel_pending`, job revoked). Map `cancel_requested` to the `cancelling` status in the tool output.
3. `when='now'`: write `scheduled_at = now`; the job gets `not_before = now + 30 s` (any `scheduled_at` within [now − 60 s, now + 30 s)).
4. The job payload takes platform options from the **bound revision** (`settings.platform_options[provider]`), so `applyChannelDefaults` must run before
   `submit()` (the M2 test does exactly this for TikTok).
5. `hub_posts_retry` (S3) reuses planning `updateTarget(…, { scheduled_at: now }, true)` + `resubmitIfWaiting`, like `post_update reschedule`.

## S7 (web and read models)

6. Job rows carry, besides Appendix A: `scheduled_for`, `media_refs`, `synced_view {hold, mode, at}`, `go_mode`, `run_mode`, `driver_trace` (dry runs;
   for `MachineDetail.last_driver_trace`), `failure {code, message}`, `owner_confirmed`, `owner_marked_not_published`, `force_released`,
   `waits_released_at`, `requeued_at` (check_login), `cancel_reason`. `result.evidence_ids` are `evidence` row ids (linked_resource_type `worker_job`).
   Evidence `file_object` rows have `purpose='evidence'` and `worker_job_id`.
7. Timeline events (`worker_job_event.event`) in addition to §3.6: `go`, `go_denied {reason}`, `missed {reason}` (go limits), `media_ready`,
   `media_unavailable`, `requeued`, `result_pending_timeout`. `detail.reason` of `missed_unclaimed` is `unclaimed` or `media_unavailable`.
8. `derivePostStatus` after `hub_jobs_force_release` of an **unreported** job: the job is `cancelled` and the task `blocked` (`force_released`), so with
   `plan_status='ready'` the frozen function returns `scheduled` although nothing will run. Suggest showing it as `missed` (or let the lead amend
   Appendix A); "改到…" works.
9. `sync_behind`: compare `machinePresence(id).applied_sync_generation` with `deviceSyncState(ctx, id).generation`; `at` is the change time.

## S8 (E2E)

10. `start(config, { beforeListen(app, services) })` now passes `services.background` (the Operation store as the background runtime sees it) for
    seeding and assertions. `apps/server/src/modules/worker/loop.test.ts` is a working in-process reference (pairing, `add-channel`, REST scheduling,
    real runtime, fixture platforms, captcha).
11. Device nonces are in memory only in hub mode (`config.hub`); development/local mode keeps `device_nonce` records (a Commands SQLite test replays a
    request across a process restart). The hub-mode E2E therefore sees the restart rule: requests signed before the hub started get
    401 `DEVICE_PROOF_EXPIRED` (the Worker re-signs).
12. Hub timing in tests comes from `config.testTiming` (`SMARTSELL_TEST_UNREPORTED_GRACE_SEC`, `…_PREPARE_LEAD_SEC`, `…_OFFLINE_STALENESS_SEC`,
    `…_READBACK_SCHEDULE_SEC`); the lifecycle scan runs every 15 s inside the publishing drain.
