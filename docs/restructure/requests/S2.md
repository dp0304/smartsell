# S2 (channels, approvals, precheck): requests to other workstreams

S2 owns `apps/server/src/modules/account/{social-accounts,channel-registration,index,registry,channel-settings,channel-ops,machine-ops}.ts`, `apps/server/src/modules/planning/index.ts`, `packages/domain/src/publishing/{index,publishing.test}.ts`, `apps/server/src/modules/content/{model,index,validation,revisions}.ts`, `packages/adapters/src/provider-catalog.ts` and their tests. Everything below is a change in a file S2 does not own, or a contract other streams must code against. Each item names the file, the function, the change and why.

## S3 (Worker job engine)

1. **Install the job engine hooks** — `apps/server/src/modules/worker/index.ts`, module top level (C3).
   S2 calls the C3 functions through an injectable hook so planning and the account ops never import `modules/worker` (that import would create a load cycle and S3 was not running while S2 was built). Until installed, the defaults never fake work: `revokeForTarget` / `moveQueuedChannelJobs` are no-ops only when no live `worker_job` exists and otherwise throw 503 `WORKER_ENGINE_UNAVAILABLE`; `createCheckLoginJob` always throws it; `bumpSyncGeneration` returns 0.

   ```ts
   import { setWorkerEngineHooks } from '../account/channel-settings.js';
   setWorkerEngineHooks({ revokeForTarget, bumpSyncGeneration, moveQueuedChannelJobs, createCheckLoginJob });
   ```

   Where S2 calls them:
   - `revokeForTarget(ctx, target, 'approval_invalidated')` — `planning/index.ts` `blockUnsent()` when `task.route[0].executor === 'worker'` and the reason is `approval_invalid` (every `retireRequest(..., 'invalidated')`, the 1-hour preflight, `applyPlanningEvent`, `refreshEvergreenTarget`, and `applyApprovalModeChange` direct → needs_approval). Must follow §5.10: never revoke the job `target.worker_job_id` points at when it still matches the current task. It must not throw for `submitting`/`result_pending` (it runs inside unrelated writes such as a settings save); leave those to the job's own result.
   - `bumpSyncGeneration(ctx, deviceIds, reason)` — every settings write (`hub_channels_update_settings`, notice ack, risk ack/clear), `hub_channels_bind_machine` (old and new device), `hub_machines_pause`/`resume`, and `publishing_pause` / `publishing_release_pause` for the devices bound to affected hub channels.
   - `moveQueuedChannelJobs(ctx, accountId, deviceId)` and `createCheckLoginJob(ctx, accountId, { openLoginWindow: true })` — `hub_channels_bind_machine` (§5.10 steps 3–4). S2 already refuses with 409 `CHANNEL_HAS_ACTIVE_JOBS` (details `post_ids`, `job_ids`) for jobs in `claimed, ready, running, submitting, result_pending, needs_owner, releasing, unreported, outcome_unknown` before calling the move.

2. **`ensureTask` Worker route** — `apps/server/src/modules/execution/service.ts` `ensureTask()`.
   `assessTarget()` now returns `route: 'worker'` for a channel account on a driver provider (and `'manual'` with risk `driver_unavailable` otherwise). Today `ensureTask` maps any non-`api` route to `{ executor: 'manual', reason: 'manual_fallback' }`; per §5.2 it should write `route = [{ executor: 'worker', device_id: binding.device_id }]` and call `dispatchWorkerJob` when `assessed.route === 'worker'`. `blockUnsent` recognises the Worker route only through `task.route[0].executor === 'worker'`.

3. **`ctx.presence` (C14)** — `integration/workspace-services.ts`. The precheck reads `ctx.presence?.(deviceId)?.last_seen_at` through the domain helper `deviceOnline(ctx, device)` and falls back to `connector_device.last_seen_at`. A throwing `presence` is treated as absent.

4. **Helpers S3 can reuse instead of re-deriving** (all in `packages/domain/src/publishing/index.ts`): `channelSettingsFor`, `channelEffectiveMode(provider, settings)` (the §3.3 truth table — use it for `go.mode` and heartbeat `mode`), `channelDayUsage(ctx, accountId, at, zone, excludeTargetId)` (daily-cap count; go check 7 counts running/published only — pass your own filter or reuse with care), `inPublishWindow(window, at, zone)` (go check 8), `deviceOnline(ctx, device)`, `TIKTOK_REQUIRED_OPTIONS`. From `account/channel-settings.ts`: `channelLabel` (blocker `channel_label`), `channelLoginState`, `approvalDeadline`.

5. **Review** of S2's changes to `planning/index.ts` and `packages/domain/src/publishing/**`: see `S2-changes-for-S3-review.md` (§11.1 requires it before merge).

## S4 (posting API and MCP)

6. **Calls into S2** (C2), all exported and tested:
   - `ensureChannelSettings(ctx, accountId)` — throws 422 `CHANNEL_PROVIDER_UNSUPPORTED` for non-hub providers (douyin, xiaohongshu). Inside a read-only transaction it returns unsaved defaults (`id: ''`, `version: 1`).
   - `applyChannelDefaults(ctx, variantId, settings.platform_defaults)` and `commitVariantRevision(ctx, variantId, { body })` live in `apps/server/src/modules/content/index.ts` (not `model.ts`: `model.ts` cannot import the revision code without a cycle). Both return `{ revision_id, changed }`; `changed: false` means nothing new was committed (same caption / same options), so do not call `updateTarget` to rebind in that case.
   - planning: `targetValues`, `createTarget`, `submit`, `updateTarget`, `cancel`, `approvalDue`, plus `resubmitIfWaiting(ctx, targetId)` (submits a hub-channel target only if it is `awaiting_approval` without a valid pending request and before its deadline — safe to call from `posting.unblock`).
   - `submit()` on a direct channel returns the target already `ready` (`approved_via='channel_policy'`). Do not call `submit()` twice: a second call on a `ready` target throws 409 `INVALID_STATE` ("Target cannot be submitted").
   - `channelMediaRule(provider, kinds)` in the domain package returns the `MEDIA_NOT_SUPPORTED` reason (X: 1 video or 1–4 images, no mixing; TikTok: exactly 1 video) so `post_schedule` and precheck `media_kind` agree.
7. **Precheck check keys S2 adds** (for `blockers` / `warnings` mapping): blockers `automation_notice`, `machine_binding`, `machine_paused`, `channel_defaults`, `daily_cap`, `publish_window`, `media_kind`, `account_status` (inactive channel); risks `machine_online`, `login_state`, `driver_unavailable` (route `manual`), `media_spec` (upload in progress); info `automation_mode` (`detail.effective_mode`). Messages are zh-Hant.

## S7 (Web and read models)

8. **Look channel settings up by account**, never by id: `channelSettings(ctx, accountId)` / `channelSettingsOrDefault(ctx, accountId)`. `Context.create` always assigns its own UUID, so the row's `id` cannot equal `social_account_id` (§3.3 deviation). For If-Match on `PATCH /hub/channels/:id/settings` send the row's `version`; a channel whose row is not written yet reads as `version: 1`, which is what the first save creates.
9. **Readiness / labels / login state**: `channelReadiness`, `channelLabel`, `channelLoginState`, `effectiveMode`, `approvalDeadline` (for `derivePostStatus`'s `approval_lapsed`). `hub_channels_update_settings` returns `{ settings, requeued_posts, revoked_posts, changed_fields, effective_mode }`; `requeued_posts` is the number for "已更新，N 則排程中的貼文已重新確認".
10. **Machine display name**: `connector_device.display_name` is written by `hub_machines_update` (and by S3 at pairing); show `display_name ?? name`.

## S6 (Worker runtime) / S9 (Worker App)

11. **`channels.register` selection fields** (`registerWorkerChannels`): `handle` (optional, lowercased, `@` stripped, `^[a-z0-9_.]{1,64}$`), `profile_key` (`^[a-z0-9-]{8,64}$`), `automation_notice_version` (must equal `AUTOMATION_NOTICE_VERSION`, else 409 `AUTOMATION_NOTICE_OUTDATED`). X `external_id` is the handle (case-insensitive, a leading `@` is accepted, stored lowercase, `^[a-z0-9_]{1,15}$`); an X `handle` different from it is rejected. Social registrations now return `profile_key`: the hub's key, fixed once created — adopt it when it differs from the one sent.
