# S6 requests to other streams

S6 (Worker runtime and drivers) codes strictly against Appendix A/B and §5.4.
The items below are what the Worker client relies on; each names the file and
the reason. Nothing here changes the frozen contract.

## S3 — hub device endpoints (`apps/server/src/modules/account/http.ts`, `modules/worker/device-jobs.ts`)

1. **`SEQ_GAP` must carry `expected` in the error envelope.** The ingress error
   handler in `account/http.ts` currently sends only `{ error: { code } }`.
   The Worker reads `error.expected` (or `error.details.expected`) to resend
   from that seq (§5.4.3). Without it the Worker cannot recover a gap.
   Suggested: `Problem(409, 'SEQ_GAP', …, { expected })` and include
   `details` fields in the envelope: `{ error: { code, expected } }`.
2. **`media.read` with a stale fence → `409 JOB_FENCE_LOST`, not 403.** §8.2
   treats 403 as "device revoked". The Worker only stops its connection on a
   heartbeat 401/403, but a 409 lets it release the job cleanly
   (`runtime/media-cache.ts`, `runtime/job-runner.ts#download`).
3. **Heartbeat v2 `jobs[]` lists every held, non-terminal job of the request.**
   A held job missing from `jobs[]` is treated as "hub no longer lists it": the
   Worker refuses to run it offline (§5.7) until a later heartbeat lists it again.
4. **`GET /api/v1/device/driver-config`** returns the raw file; its sha256 must
   equal heartbeat `driver_config.sha256` and its `version` field must equal
   `driver_config.version`, otherwise the Worker keeps the old table and reports
   `drivers[].health='unknown'` (§8.11).
5. **`401 DEVICE_PROOF_EXPIRED` keeps the `Date` header** (Fastify default) so the
   Worker can correct its clock and retry once (§8.2).
6. **Evidence `PUT`**: any 2xx body is accepted; 4xx is recorded as rejected and
   the report that cites the hash is still sent (facts are never held back).
7. Reports arrive with `seq` restarting at 1 per new fencing token, and an
   `event_id` that is stable across resends and renumbering (renumbering after
   `SEQ_GAP` keeps the event_id).

## S2 — channel registration (`apps/server/src/modules/account/channel-registration.ts`)

8. `channels.register` selections from the Worker carry `kind:'social'`,
   `platform:'x'|'tiktok'`, `external_id` (X handle, TikTok numeric User ID),
   `handle`, `display_name`, `observed_at`, `profile_key` (`ch-<12 hex>`) and
   `automation_notice_version` (`automation-notice-2026-11`), exactly as §8.16.

## S9 — App shell (`apps/connector-desktop/package.json`, `scripts/build.mjs`, `src/main.ts`)

9. Add `"@smartsell/contracts": "workspace:*"` to `apps/connector-desktop/package.json`
   (and run `pnpm install`). Until then `src/runtime/contracts.ts` re-exports
   `packages/contracts/src/phase1.ts` by path; afterwards that one file switches to
   `export * from '@smartsell/contracts'`.
10. Installer builds must define `RELEASE.packaged = true` (esbuild `define` in
    `scripts/build.mjs`). `chrome.ts#isPackagedBuild()` reads it; every
    `SMARTSELL_TEST_*` switch and `FileVault` are refused when it is true.
11. Start the Worker with `createWorkerRuntime()` from `src/runtime/worker.ts`
    (identity from `vault.ts`, `bundledClip` = `resources/test-clip.mp4`,
    `posture`/`remoteAccess` providers from `app/posture.ts`). Use
    `runtime.events` (C11 plus the additive `connection` and `jobs_changed`
    events), `runtime.snapshot()`, `runtime.emergencyStop()` / `runtime.resume()`,
    and `enrollChannel()` + `registerEnrolledChannel()` from `src/runtime/enroll.ts`
    for 「新增帳號」. Emit `runtime.events.emit('vault_locked')` when `safeStorage`
    cannot decrypt the key.
12. The additive events in `runtime/events.ts` (`connection`, `jobs_changed`) need
    S9 review per §11.1.

## S8 — E2E (`tests/e2e-phase1/stack.ts`)

13. Fixtures: `startPlatformFixtures({ port })` returns `origins` ready for
    `SMARTSELL_TEST_PLATFORM_ORIGINS`; `setScenario`, `posts()`, `pageLoads()`,
    `ownerClick()`, `events()` and `reset()`; HTTP equivalents under `/__fixture/*`.
    Optional `slowUploadMs` (default 40 s), `uploadMs`, `xProcessingMs`.
14. Headless runner: `SMARTSELL_TEST_MODE=1` and `SMARTSELL_TEST_PLATFORM_ORIGINS`
    are mandatory (it refuses to reach a real platform). `pair` takes
    `--platform darwin|win32` on Linux CI. Output is one JSON object per line.
