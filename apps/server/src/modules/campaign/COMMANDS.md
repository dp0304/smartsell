# Campaign workspace commands

Call `POST /api/v1/workspaces/{wid}/commands/campaign/{action}` with an `Idempotency-Key` and a JSON body. The module exports `commands` through `index.ts` and uses the async workspace-scoped `Context`. Whole-command rollback and idempotent replay are host responsibilities. Read actions accept `campaign_id` unless specified otherwise. For updates, supply the version of the record the command changes as `expected_version`.

| Capability | Actions and request fields |
| --- | --- |
| Campaign | `list` accepts optional `status` (string or array), `brand_id`, `active_on` (timestamp). `get_context` joins related records and returns `null` for unknown goal progress. `create_draft` takes `brand_id`, `name`, `kind`, optional timezone, date window, owner, audience, objective, `utm_key`, and initial `markets`, `products`, `goals`. `update` takes `patch`. `transition` takes `to`, optional `reason`. `auto_transition` takes `{}`. |
| Relationships | `set_markets` and `set_products` replace the active associations. Market entries take `market_id`, optional `locales`, date window, owner and status. Products take `product_id`, optional `variant_ids`, `market_ids`, and `role`. |
| Goals | `list_goals`, `create_goal`, `update_goal`, `withdraw_goal`. A goal needs `metric_key`, `unit`, `baseline_value`, `target_value`, and `due_at`, plus `currency` for currency goals. Use `campaign_market_id` for a market-scoped goal or `market_id` in a new campaign's inline goals. Update and withdrawal take `goal_id` and `reason`. Updates take `patch`. |
| Channels | `list_plan_slots`, `create_plan_slot`, `update_plan_slot`, `remove_plan_slot`, `matrix`, `create_gap_items`. A slot needs `stage` and `platform`; optional dimensions include `social_account_id`, `market_id`, `locale`, `content_format`, `window_start`, `window_end`, and `planned_count`. Gap creation takes `slot_id`, `production_due_at`, optional `count` (at most 20) and `dry_run`. |
| Brief | `list_briefs`, `create_brief`, `list_brief_revisions`, `update_brief_draft`, `submit_brief_revision`, `approve_brief_revision`, `request_brief_changes`. Create takes `title`, optional `kind` and `campaign_market_id`. Draft takes `brief_id`, its version, either `body_doc` or `markdown`, and optional `requirements` and `fact_refs`. Review actions take `brief_id`, `revision_id` and the revision version. A change request requires `reason`. |
| Milestones | `list_milestones`, `create_tasks`, `check_milestones`. Tasks take `key`, `title`, `kind`, `due_at`, optional `owner_user_id`, `gate`, and `dependencies` (`predecessor`, optional `lag_hours`). A predecessor can refer to an existing campaign work item or an earlier key in the same batch. |
| Tracking | `list_links`, `prepare_link`, `create_link`, `get_tracking_config`, `set_tracking_config`. Link creation takes a Traffic destination and optional `utm_params`; Campaign supplies `utm_campaign`. Tracking config takes `conversion_goals`, `default_attribution_window_days`, and optional `landing_targets`. |
| Budget | `list_budget_lines`, `create_budget_line`, `update_budget_line`, `remove_budget_line`, `list_cost_commitments`, `create_cost_commitment`, `transition_cost_commitment`, `list_cost_entries`, `create_cost_entry`, `void_cost_entry`, `budget_summary`. Lines take `category`, `amount_minor`, `currency`, `fx_date`. Commitments start `pending_approval`; a lead records the approval reference when transitioning to `committed`. Release requires a reason. An entry takes `budget_line_id`, `amount_minor`, `incurred_on`, optional `commitment_id`, `currency`, `fx_date`, `fx_rate_id`, `attachment_file_ids`, `source`, and `source_ref`. |
| Closeout | `closeout_draft`, `closeout`, `get_closeout`. A wrapping campaign can capture a finalized Analytics `report_version_id` and a `retrospective_doc`. Finalizing requires the campaign version, `checklist_complete: true`, and reasons in `retained_items` keyed by `type:id` for each open issue. |
| Templates | `list_templates`, `create_template`, `update_template`, `archive_template`, `instantiate_template`. Create takes a closed `campaign_id` and `name`. Updates use `template_id` and version. Instantiation takes `template_id`, `brand_id`, `name`, `starts_at`, and optional owner. |

Campaign editors, admins and owners can draft and plan. Reviewers, admins and owners review brief revisions. Admins and owners manage budget lines, record commitment approvals, run scheduled checks, finalize closeouts and manage templates. All workspace roles can read.

## Integration

- Planning reads `ctx.get('campaign', 'campaign', campaign_id)` and requires `data.status === 'active'` when attaching the campaign. Normalized UTC `data.starts_at` and `data.ends_at` define its scheduling window. `campaign.campaign.status_changed` includes `campaign_id`, `from`, `to`, `status` and, when applicable, `reason`. Planning owns enforcement of publish pauses. The host can invoke `auto_transition` every five minutes and `check_milestones` hourly per campaign.
- The matrix reads Content, Planning and Execution records in the workspace transaction. It counts each publish target once, surfaces unmatched actuals and reports overlapping slots. An unscheduled variant created from a gap stays assigned to that slot. The other matrix matches use platform, configured dimensions, stage metadata and the half-open scheduling window. `workspace.work_item.due_at` is the production deadline. `planning.publish_target.scheduled_at` is the publication time. Completing a milestone exposes a scheduling gate.
- Traffic owns short links, destination validation, redirects and click records. Analytics owns the metric dictionary (`analytics.metric_definition.data.key`), goal progress (`analytics.campaign_goal_progress`) and report versions. The campaign closeout stores report output and its cutoff separately from the capture time of live campaign data. Creator records supply open commission or sample obligations. Later Analytics reports leave the stored closeout snapshot intact.
- The budget summary preserves original currency and conversion dates and groups totals by currency. Costs use a matching-currency budget line. Remaining amount equals allocation minus actual spend and outstanding approved commitments. Overruns emit a campaign event and create a pending Core approval request. The campaign ledger records approval references and leaves spend execution to Ads and Creator workflows. Historical cost entries stay auditable through voids.
- Templates copy structural fields and relative offsets. Briefs and milestone titles start as placeholders. Instantiating creates a fresh draft and UTM key. Prices, cost records, fact references, rights, content and publish targets stay with the source campaign.
